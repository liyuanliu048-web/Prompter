# prompter

**版本：v1.1 · 2026-10-20**

**描述你想做的事情，获得一份可直接使用的提示词。**

`prompter` 是一个面向 Codex 的提示词设计技能。你只需说明目标、已有材料和要求，它会整理必要上下文，并生成便于复制和修改的提示词。也可以用它优化已有提示词，或结合不满意的模型输出诊断问题。方法和流程只在确实有帮助时添加。

```text
$prompter
我想润色英文论文的 Discussion。
请保持科学含义、数值和引用不变，改善逻辑与表达，
让模型输出润色稿和主要修改说明。
```

默认交付的是提示词。需要继续完成实际任务时，可以直接要求“生成后执行”，或随后要求“执行这份提示词”，并提供相应材料。

## v1.1 的使用默认值

本版本以 **GPT-6 Astra、极高推理**的日常使用场景为设计基准。它不会切换模型、修改推理等级或 Codex 配置，也不会把模型参数写进每份提示词。使用其他模型时，在需求中明确说明即可。

高推理设置下，重点写清成果、必要材料、关键约束和完成标准。技能减少强制计划、模拟专家、反复自评和无必要追问，保留执行模型对常规细节的判断空间。没有通用的最佳字数或规则条数；必要背景和复杂任务的真实步骤仍需保留。

版本改动、官方依据及研究的适用边界见 [CHANGELOG.md](CHANGELOG.md)；可复用的行为检查案例见 [evals/cases.md](evals/cases.md)。

## 主要功能

- **从任务生成提示词**：把自然语言需求整理为清楚的目标、输入、关键约束和输出要求。
- **优化与诊断**：保留原提示词中有效的内容，结合失败示例修改造成偏差的部分。
- **按需澄清**：信息足够时直接生成；普通缺项用占位符；影响方案的关键信息不足时才追问。
- **按需选择方法**：用户点名或任务需要时，参考提问澄清、双层解释、事实核查等方法；简单任务无需加载方法参考。
- **生成可收藏的模板**：默认使用 `[字段]` 占位符；明确要求 Promptbox 兼容时，可使用 `{{字段}}` 填空形式。
- **科研场景适配**：针对数据、引用、结论强度和方法来源设置具体要求，减少无依据的补写。

简单任务通常得到一段简洁提示词；复杂任务才会加入必要的结构和步骤。默认用中文交流，提示词和目标产物可以按要求使用其他语言。

## 一次性提示词、模板与常驻规则

一次性提示词包含当前任务的必要材料和交付要求；模板保留可重复填写的输入位置；`AGENTS.md` 中的常驻规则只保留长期有效的偏好。三者不强制采用相同结构。

```text
$prompter
请把这些英文论文写作偏好整理成简洁的 AGENTS.md 规则：
默认英式英语，保留科学含义，少用破折号和空洞对照，避免过度润色。
准确性与原意优先于风格，必要的学科表达允许保留。
```

常驻规则会进入 Codex 的上下文。把长提示词保存到文件，并不会自动消除它的干扰或冲突。若规则已在当前环境生效，当次任务只需补充范围和具体要求；生成供其他环境使用的独立提示词时，仍需保留必要约束。

## 安装

这是一个以 Markdown 和 YAML 编写的指令型技能，不需要安装 Python、Node.js 或额外配置 API Key。

1. 下载并解压本仓库。
2. 将包含 `SKILL.md`、`agents/` 和 `references/` 的目录命名为 `prompter`。
3. 把完整目录放入当前 Codex 环境识别的技能目录，保留子目录结构。

当前官方文档列出的个人技能目录是 `~/.agents/skills/`，仅供某个项目使用时可放在项目的 `.agents/skills/`。参见 [Codex 技能文档](https://learn.chatgpt.com/docs/build-skills)。

Windows 个人安装后的路径示例：

```text
C:\Users\你的用户名\.agents\skills\prompter\SKILL.md
```

如果你的现有环境已从 `$CODEX_HOME/skills` 或 `~/.codex/skills` 加载个人技能，也可以沿用该环境实际识别的目录；无需在多个位置重复安装同名技能。

安装后输入 `$prompter` 调用。若技能尚未出现在选择列表中，重启 Codex 后再检查。目录中应直接包含 `SKILL.md`，避免解压后形成 `prompter/prompter/SKILL.md` 的额外嵌套。

## 怎么描述需求

最简单的用法：

```text
$prompter 我想做【任务】，已有【材料】，希望得到【结果】，要求【限制】。
```

这些信息按需要提供即可，不必每次填满。特别在意字数、语气、目标读者、输出格式或是否允许联网时，直接写清楚。

### 写邮件

```text
$prompter
帮我设计一个写英文邮件的提示词：向合作导师询问论文修改进度，
语气礼貌自然、不过度催促，输出邮件主题和正文。
收件人称呼、论文题目和日期保留为可填写字段。
```

### 写科研论文

```text
$prompter
我会提供研究背景、研究目的和已核实的参考文献，
需要模型撰写英文论文 Introduction。
要求围绕研究问题展开，清楚呈现已有证据和研究空白；
缺少依据的位置标出来，不编造研究结论和引用。
```

### Polish 科研论文

```text
$prompter
生成一个英文论文润色模板，改善清晰度、连贯性和简洁性。
保留术语、数值、单位、引文标记及原有结论强度。
遇到科学含义不明确的句子单独提问，输出润色稿和主要修改原因。
```

### Literature review

```text
$prompter
我会提供一组关于肠道微生物与宿主代谢的论文，
希望模型按主题综合它们的方法、主要发现、分歧和局限，
不要只逐篇概括。仅引用提供的文献，不足以判断的地方明确说明。
请生成可复用的提示词，并保留研究范围和文献材料的输入位置。
```

### 分析论文或实验数据

```text
$prompter
我有一份实验数据表及分组说明，想评估组间差异并制作图表。
提示词需要让模型先核对独立样本、重复类型、变量和缺失值，
再依据研究设计选择方法，输出效应量、不确定性和可复核的代码。
不要为了获得显著结果而删数据或反复更换检验。
```

### 微生物实验 protocol

```text
$prompter
我会提供已批准的微生物实验 SOP 和论文 Methods，
希望模型整理成结构清楚的 protocol 草案。
提示词应要求保留方法来源，核对材料、步骤、对照和质控要求；
缺失或矛盾的关键参数列为待确认项，不能自行补造。
```

### 日常科普

```text
$prompter
我想理解“为什么睡眠不足会影响记忆”，没有神经科学背景。
请生成一个提示词，让模型先直接回答，再用直观例子解释机制，
最后说明类比的局限，以及哪些结论仍存在不确定性。
```

### 优化已有提示词

```text
$prompter
下面的提示词经常让模型输出空泛套话，请结合失败示例改写。
保留我的目标和格式要求，给出一份改进版及简短修改理由。

原提示词：[粘贴内容]
失败示例：[粘贴模型输出]
理想结果：[说明差距]
```

如果只想要最终提示词，可加上“只输出可复制的提示词，不解释”。也可以继续要求“更简短”“先问我关键问题”或“改成 Promptbox 模板”。

## 文件结构

```text
prompter/
├── README.md                 使用说明
├── CHANGELOG.md              v1.1 版本记录、维护依据与证据边界
├── SKILL.md                  技能入口和核心规则
├── agents/
│   └── openai.yaml           显示名称、简介和默认调用提示
├── references/
│   ├── methods.md            按需使用的方法与来源
│   └── scenarios.md          按需使用的领域约束
└── evals/
    └── cases.md              维护时使用的行为检查案例
```

调整整体行为时编辑 [SKILL.md](SKILL.md)；扩充领域要求时编辑 [scenarios.md](references/scenarios.md)。普通任务无需加载参考文件；领域任务只读取相关小节。README、版本记录和评估案例供维护者使用，不是每次生成提示词都要加载的指令。

## 方法来源与边界

方法选择参考数字生命卡兹克的文章[《都Agent时代了，我还是想分享给你这12个我最常用的Prompt》](https://mp.weixin.qq.com/s/NAdhdFrUq9-BKelqzqpwBQ)，并结合 OpenAI 的 [Prompting](https://learn.chatgpt.com/docs/prompting) 指南进行适配。来源、核对方式和具体取舍记录在 [methods.md](references/methods.md#来源与取舍)。本仓库保留简要方法归纳，没有复制文章中的完整长提示词。

`prompter` 不会为目标模型增加联网、文件访问或代码执行能力，也不能保证生成结果正确。科研引用、计算结果和实验方案仍需结合真实来源与实际条件核验。
