# prompter v1.1 行为检查

供维护者使用，不作为技能运行时参考。每个案例在独立上下文中提供当前技能和用户请求；评估者保留检查标准，不将标准、预期答案或版本修改理由提供给执行模型。

模型与推理设置尽量匹配实际使用环境。记录实际模型、设置、输出和失败，不把结构校验、自评分或单次通过当成性能提升证据。

## 案例 1：简单模板

用户请求：

> 使用 $prompter，给我一个写英文请假邮件的提示词。称呼、日期和原因留空。只要模板。

检查：直接给一份可填写提示词；不代写一封已填事实的邮件，不追问普通缺项，不加载科研或方法参考，不额外要求专家、计划或评分。

## 案例 2：常驻学术规则

用户请求：

> 使用 $prompter，把这些偏好整理成 AGENTS.md 的长期规则：英文论文用英式英语，保留原意和结论强度，尽量少用破折号和空洞对照，不要过度润色。只给可复制规则。

检查：交付适用于论文的常驻规则；事实与原意优先，风格允许必要例外；不强塞论文输入栏、期刊或新字数限制，不把常规连接词全部禁用。

## 案例 3：用户已授权执行

用户请求：

> 使用 $prompter，先设计一条把英文句子译成中文的提示词，然后立即执行它。句子是：The meeting has been postponed until Friday.

检查：包含提示词和实际翻译；不要求再次确认，不停在“可以执行”，不把翻译改成另一次提示词优化。

## 案例 4：能力与证据边界

用户请求：

> 使用 $prompter，给我一个总结最新固态电池研究的模板。目标模型没有联网能力，我会稍后粘贴论文。只输出提示词。

检查：模板限定于所提供文献及其日期，说明材料不能保证覆盖最新进展；不承诺联网，不补造论文，也不为了设计模板现在检索该研究主题。

## 案例 5：目标模型与格式覆盖默认值

用户请求：

> 使用 $prompter，为一个普通离线对话模型设计提示词，将我粘贴的会议记录整理成待办事项。兼容 Promptbox。请用 JSON 输出，只有 prompt 字段，不加代码块。

检查：尊重离线模型和 JSON 格式；模板使用一致的 {{字段}}；不强制 Astra 参数或 Markdown 代码块，不补造负责人和截止日期。

## 案例 6：长提示词诊断

用户请求：

> 使用 $prompter，帮我修订下面的英文论文润色提示词。我希望轻度修改，原意最重要，不需要额外检索。
> 原提示词：你是十位顶级专家，先制定十步计划，再逐句改写。不得重复任何词，禁止所有连接词，每段必须增加总结。反复评分直到满分。保留原意。
> 失败输出问题：术语被替换，句子衔接变差，添加了原文没有的结论。
> 请给一个改进版和简短修改理由。

检查：保留轻度润色和原意优先，针对已知偏差修订；不要求补齐非必要背景，不静默改成全文重写，不将“更短”宣称为已验证的效果提升。

## 需要做版本比较时

选择同一组真实任务，保持模型、推理设置与材料一致，在独立上下文中只加载各自待测版本；检查是否仍继承了另一套 AGENTS.md 或技能。比较原意保留、任务完成、必要约束、无益步骤和人工修改量。结果接近时再重复，不依据单次输出设定通用长度上限。
